# ups-agent

Мониторинг источника бесперебойного питания (ИБП) по протоколу SNMP и автоматическое
завершение работы системы при сбое электропитания.

Программа:

- периодически опрашивает SNMP-карту ИБП (polling);
- принимает SNMP-трапы от ИБП;
- пишет журнал событий с уровнями серьёзности;
- инициирует корректное отключение хоста (и, при необходимости, самого ИБП) при
  низком заряде батареи, истечении оставшегося времени работы или по критическим
  трапам;
- позволяет выводить текущий статус ИБП и управлять конфигурацией SNMP-карты.

## Возможности

- Получение состояния ИБП по SNMP (модель, статус выхода, напряжение/частота сети,
  напряжение/частота выхода, нагрузка, ёмкость и температура АКБ, оставшееся время
  работы, прошивки и т. д.) — команда `status`.
- Чтение, запись и сброс к заводским настройкам конфигурации SNMP-карты —
  команда `cardconfig`.
- Приём SNMP-трапов с проверкой адреса источника и community.
- Автоматическое отключение системы по нескольким независимым условиям:
  - низкий заряд АКБ (по данным ИБП);
  - ёмкость АКБ ниже или равна `powerctl.batterylevel`;
  - оставшееся время работы меньше или равно `powerctl.minutes`;
  - время работы от АКБ больше или равно `powerctl.timeout`;
  - критические трапы, требующие немедленного завершения работы.
- Опциональное отключение самого ИБП перед выключением хоста
  (`powerctl.upspoweroff`).

## Требования

- Linux (используется `syscall.Sync` и `seteuid(0)` при выключении хоста);
- Go 1.27.1 или новее;
- ИБП с SNMP-картой (например, поддерживающей MIB `Upsmate.mib`).

## Сборка

```sh
go build -o ups-agent .
```

Собранный бинарник и конфигурационный файл размещаются в одном каталоге, например
`/opt/ups-agent/`.

## Конфигурация

Программа использует конфигурационный файл `ups-agent.yml`, который по умолчанию
ищется рядом с исполняемым файлом. Путь к нему можно изменить флагом `-config`.

Пример конфигурации приведён в `ups-agent.yml`. Основные секции:

| Секция | Параметр | Описание |
| ------ | -------- | -------- |
| — | `upsname` | Имя ИБП (необязательно). |
| — | `model` | Модель ИБП (необязательно). |
| `logger` | `level` | Уровень журнала: `emerg`, `alert`, `crit`, `error`, `warn`, `notice`, `info`, `debug`. |
| `logger` | `logdir` | Каталог журнала (по умолчанию `logs`). |
| `logger` | `filename` | Имя файла журнала (по умолчанию `ups-agent.log`). |
| `powerctl` | `batterylevel` | Порог ёмкости АКБ в процентах для отключения (по умолчанию `10`). |
| `powerctl` | `minutes` | Порог оставшегося времени работы для отключения (по умолчанию `10m`). |
| `powerctl` | `timeout` | Максимальное время работы от АКБ (по умолчанию `0s` — отключено). |
| `powerctl` | `poweroff` | Выполнять ли отключение хоста (по умолчанию `true`). |
| `powerctl` | `poweroffcmd` | Команда отключения (по умолчанию `/sbin/poweroff`). |
| `powerctl` | `upspoweroff` | Выключать ли ИБП при завершении работы (по умолчанию `false`). |
| `snmp` | `addr` | IP-адрес SNMP-карты ИБП (обязательно). |
| `snmp` | `community` | SNMP community для чтения (по умолчанию `public`). |
| `snmp` | `polltime` | Интервал опроса (по умолчанию `60s`). |
| `snmp` | `trapcommunity` | SNMP community для приёма трапов (по умолчанию `public`). |
| `snmp` | `traplistener` | Адрес для приёма трапов, например `0.0.0.0:162`. |
| `cardconfig` | … | Параметры конфигурации SNMP-карты (см. `ups-agent.yml`). |

Длительности задаются в формате Go (`30s`, `10m`, `2h` и т. п.).

### Проверка конфигурации

```sh
./ups-agent -configtest
./ups-agent -configdump   # вывести итоговую конфигурацию
```

## Использование

### Запуск демона

```sh
./ups-agent
```

Демон принимает сигналы:

- `SIGHUP` — переоткрыть файл журнала (для ротации);
- `SIGINT`, `SIGTERM`, `SIGQUIT` — корректная остановка.

### Статус ИБП

```sh
./ups-agent -status
```

Выводит текущее состояние ИБП: модель, статус выхода, напряжения, частоту, нагрузку,
состояние и ёмкость АКБ, оставшееся время работы и т. д.

### Управление конфигурацией SNMP-карты

```sh
./ups-agent -cardconfig get      # прочитать настройки карты
./ups-agent -cardconfig set      # записать настройки из секции cardconfig
./ups-agent -cardconfig default  # сбросить карту к заводским настройкам
```

Значения для записи задаются в секции `cardconfig` конфигурационного файла; допустимые
значения каждого параметра перечислены в комментариях `ups-agent.yml`.

## Логика отключения

При обнаружении любого из следующих условий агент инициирует отключение системы:

- статус АКБ ИБП — «низкий заряд»;
- ёмкость АКБ `<= powerctl.batterylevel`;
- оставшееся время работы `<= powerctl.minutes`;
- время работы от АКБ `>= powerctl.timeout` (если `timeout > 0`);
- приход критического трапа, помеченного флагом `shutdown`
  (например, `upsLowBatteryShutdown`, `upsEmergencyStop`, `upsOverLoadShutdown`).

Если задан `powerctl.upspoweroff`, перед выключением хоста агенту отправляется команда
выключения самого ИБП, затем выдерживается пауза 5 секунд для доставки SNMP-пакета.
Отключение хоста выполняется однократно (защита `sync.Once`).

## Установка как службы systemd

В каталоге `contrib` подготовлены вспомогательные файлы:

- `contrib/ups-agent.service` — unit-файл systemd;
- `contrib/ups-agent.logrotate` — конфигурация ротации журнала;
- `contrib/prepare-traps.pl` — утилита для генерации карты трапов из MIB
  `card/Upsmate.mib`.

Установка службы:

```sh
# разместить бинарник и конфигурацию
sudo mkdir -p /opt/ups-agent
sudo cp ups-agent ups-agent.yml /opt/ups-agent/

# создать пользователя
sudo useradd --system --no-create-home --shell /usr/sbin/nologin ups-agent

# установить unit-файл и запустить службу
sudo cp contrib/ups-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ups-agent
```

Для корректного отключения хоста процессу требуются capability `CAP_SETUID`
(выполнение `seteuid(0)`) и `CAP_NET_BIND_SERVICE` (приём трапов на порту 162), что
уже учтено в unit-файле через `AmbientCapabilities`.

Если приём трапов настроен на порту `162`, а служба работает под непривилегированным
пользователем, capability `CAP_NET_BIND_SERVICE` позволяет слушать этот порт.

Чтобы демон не завершался периодически службой systemd для пользователя без активной
сессии, выполните:

```sh
loginctl enable-linger ups-agent
```

### Ротация журнала

Установите конфигурацию ротации и при необходимости скорректируйте путь:

```sh
sudo cp contrib/ups-agent.logrotate /etc/logrotate.d/ups-agent
```

Ротация отправляет демону сигнал `HUP` (`pkill -HUP ups-agent`), по которому агент
переоткрывает файл журнала.

## Структура проекта

| Каталог | Назначение |
| ------- | ---------- |
| `card` | Работа с SNMP-картой ИБП: OID, опрос, трапы, статус, отключение. |
| `cardconfig` | Управление конфигурацией SNMP-карты (`get`/`set`/`default`). |
| `config` | Загрузка и проверка конфигурации, разбор аргументов командной строки. |
| `log` | Журналирование с уровнями серьёзности. |
| `monitor` | Цикл мониторинга и принятие решения об отключении. |
| `poweroff` | Отключение хоста и ИБП. |
| `status` | Вывод статуса ИБП. |
| `contrib` | Файлы для systemd, logrotate и утилита генерации карты трапов. |
